Overview

A focused voice experiment, not a giant platform.

The project keeps the moving parts easy to understand: one inbound voice webhook, one speech-response route, and one optional local model connection.

Current scope: Programmable Voice only. Inbound calls, Twilio speech recognition, and local Ollama response generation. No SMS, Verify, WhatsApp, outbound dialer, call recording, or contact database.
01

Inbound voice

Twilio sends an incoming call to the Express webhook and TwiML gathers the caller's speech.

02

Local model

Recognized speech can be sent to an Ollama model running on the same machine or local network.

03

Graceful fallback

If Ollama is unavailable, the call still receives a simple response instead of failing silently.

04

Small codebase

The current prototype uses Node.js, Express, and the Twilio SDK with no database dependency.

05

Webhook validation

Public voice routes validate Twilio request signatures when the real public URL and token are configured.

06

No recording by default

The current version does not include call recording, transcript storage, or a persistent conversation database.

Architecture

Simple enough to trace from end to end.

The current version is intentionally one-turn. That keeps development predictable while the voice path, local model path, and security boundary are tested.

  • Twilio handles telephony and speech collection.
  • Express receives the webhook and prepares TwiML.
  • Ollama is optional and stays outside the Twilio credential path.
  • The spoken answer is returned to the caller through Twilio.

Security and privacy

Keep the prototype small, keep the data path clear.

The current design avoids storing more data than it needs and keeps credentials outside the model prompt.

Secrets
Environment only

Twilio credentials stay in a local .env file and are excluded from Git.

Webhooks
Signature checked

Public voice requests are validated with Twilio's request signature.

Speech
Twilio handles recognition

Caller speech is collected through Twilio Gather. The resulting transcript is what the application sends to local Ollama.

Storage
No database yet

The current prototype does not intentionally persist call audio or transcripts.

AI boundary
No Twilio secrets sent to Ollama

The model receives recognized speech text, not Twilio credentials.

FAQ

Common questions.

Is this the official Freebot project?

No. This repository is an independent voice experiment inspired by and intended to explore integration with the upstream Freebot project.

Does it require Ollama?

No. Ollama is optional. Without it, the voice route returns a simple fallback response so the telephony flow can still be tested.

Does it use SMS, WhatsApp, or OTP verification?

No. The current project scope is Twilio Programmable Voice only.

Does "local AI" mean the entire call stays local?

No. Twilio handles telephony and speech recognition. Only the language-model response generation is local through Ollama.

Does it record calls?

No call-recording feature is included in the current prototype.

Is this production ready?

No. It is an early development prototype. Production use would need broader testing, monitoring, operational controls, and a review of the requirements that apply to the deployment.
